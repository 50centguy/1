# UnifiedClinic — phase 1 environment (V1 room + V4 trade placement)

Everything here is generated by one deterministic script, `build_unified_clinic.py`. It was run in Blender 5.2.2 LTS, and that run produced the files listed below. Nothing here has been placed or tested in Unity.

```
D:/steam/steamapps/common/Blender/blender.exe -b --factory-startup --python ArtSource/UnifiedClinic/build_unified_clinic.py
#   append  -- norender   to skip the 9 EEVEE renders (build + checks + exports only, ~6 s; full run ~45 s)
```

## Coordinate contract
Layout constants are in Unity space (+Y up, +Z north, +X east, metres). Blender `b = (-ux, -uz, uy)`. The FBX is exported like WorkbenchArea/Unit07ServiceDock (`axis_forward=-Z, axis_up=Y`). Place the `UnifiedClinic` root at Unity (0,0,0) and keep its import rotation (-90,0,0). The anchor round trip was tested in Blender only, not in Unity.

## Layout (measured)
- Octagonal room, apothem 3.40 m, ceiling 3.00 m. **One entrance, on the south side**: clear opening 1.20 × 2.20 m, with two sliding leaves (`uc_slide_axis_unity_world`, `uc_close_offset_unity`).
- Existing assets are not modelled here. The program places them using these anchors:
  - WorkbenchArea root (0, 0, 2.35), yaw 180. Its `Room_*` children and the hide list in `checks.json` should be disabled.
  - Dock root (-2.73, 0, 0), yaw 90. The robot faces east.
- **Main aisles**, measured as perpendicular clear width with reserved work zones counted as blocked:
  - entrance → west → bench: **1.14 m** (1.29 m raw)
  - entrance → east → trade: **0.92 m** (1.18 m raw)
  - north cross aisle: **1.11 m**
  - operator entry behind the counter: **0.73 m** (required 0.70)
- **Surgery bed and tool ring**:
  - Pad top 0.85 m. Ring at 2.45 m.
  - 7 hanging tools park at 1.56–1.90 m and reach 1.01–1.06 m when lowered, which is 0.11–0.16 m above the bed's highest point.
  - Allowed boom yaw per tool is reported in `checks.json` (lamp ±4°, up to ±30°).
  - Nothing outside the bed footprint hangs below 2.0 m.
- **Trade (V4 placement)**:
  - Counter centre line x = 1.90, top 0.95 m, plus an angled SE segment.
  - The stool is inside the counter: 0.12 m from the counter edge and 0.32 m from the east shelving.
  - The desktop CRT screen faces +X, toward the operator and east wall. The screen normal is 12° from the seated eye, at 0.48 m. Its ventilated back faces the room. There is no ceiling arm.
  - Two pads with a 0.80 m gap and the CRT between them:
    - Receive/incoming-next-job pad: south, (1.84, 0.956, -0.60)
    - Deliver/outgoing-repaired pad: north, (1.84, 0.956, 0.60)
  - Both pads are 0.86 m from the operator's shoulder.
  - Each pad has a room-facing status lamp (`EMPTY=off, CARGO=on, READY=blink`; the program toggles emission). Screen text is a texture only.
- **Workbench support (V1)**:
  - Rear wall-rail carriage with a 2-link arm, head and monitor tilt. Pivots and axes are stored in object props.
  - Measured free joint ranges from the default pose: carriage ±0.25 m, link1 -98..+8°, link2 -170..+18°, head -54..+76°, tilt ±44°. Each range is limited by bench pegboard, shelf or cabinet contact; see `checks.json`.
  - There are no ceiling twin screens.

## Checks — what is real vs proxy
- **Real meshes:** the `UNIT07_ServiceDock.fbx` and `WorkbenchArea.fbx` exports are imported read-only and tested against the environment. Dock and bench feet sit ≤1 cm below y=0 and are reported as resting contact (`floor_resting_min_y`), not clashes. Other checks:
  - bench drawer and door travel
  - dock disassembly corridors (boxes from the dock script)
  - 0.10 m parking margin around the dock and robot
- **Proxy only:** the robot is the `UNIT07_RobotPlaceholder.fbx` bounding blocks. **The actual RobotV4 mesh was not tested.**
- Not done: Unity import, dynamic collision, NavMesh, human/VR walk-through, gameplay.

## Fixed in this pass (the script from the prior attempt had never run)
1. `MB.cyl` crashed when given a free axis vector.
2. Parent-inverse used a stale `matrix_world`, which doubled child offsets. This put the stool seat at x = 5.2 and the gantry tools above the ceiling.
3. The west wall frame and cables were inside the dock parking margin. They now sit at z = ±0.95.
4. East shelving moved back 4 cm. The operator entry went from 0.69 to 0.73 m.
5. The operator-entry check counted its own destination zone as blocked. Reserved-zone edges now sit at the counter-top edge, and the corner counter-top overhang (0.90–0.95 m, knee space) is allowed explicitly.
6. The trade CRT texture was mirrored from the operator seat, and the bench render label was backwards.
7. Rust on the shared worn texture was toned down. It was reading as a dominant orange-brown.
8. `materials.json` now uses the WorkbenchArea schema.

## Differences from the approved references / open gaps
- This is a density first pass. The clutter is limited: rags, mugs, bottles, salvaged limbs, crates, bins and cables, all pooled by material. Coats on hooks, more patch repairs and wall-cable density from V1 are still sparse.
- Gantry tools and hangers are blocky boxes and tubes. The V1 concept has finer, rounder surgical tooling.
- Lighting is EEVEE render lighting only. Unity lights are not authored, and the trade lamps and screen need program-driven emission.
- Trade screen text is static texture art. Live status text needs a program overlay; the anchor is `TradeScreen`.
- The east-entrance aisle is only 0.92 m when zones count as blocked, just above the 0.90 m minimum. Do not add clutter west of the counter.
- Some hanging tools have tight boom-yaw limits (lamp ±4°) when lowered over the bed. Gameplay must clamp to `allowed_boom_yaw_deg` or the lamp should be shortened.
- Two overhead render labels are partly cut at the image edge (render-only, cosmetic).
- `WorkbenchArea` children on the old side walls must be hidden in Unity by the program, using the list in `checks.json`.
