## 20. 手术病人上台流程验证（2026-10-22）

病人是罗亚（港区装卸工，吊机 3 组，租用的右臂被远程锁死）。角色模型之后由用户用 Tripo 制作，这一节只验证动作流程。实现是 `Runtime/SurgeryPatientRuntime.cs`。

- **占位人体**：关节命名沿用 Unity Humanoid 骨骼（Hips、Spine、Chest、Neck、Head、Left/Right UpperLeg/LowerLeg/Foot、UpperArm/LowerArm/Hand），用基本几何体拼成。右前臂为灰色锁死义体，带红灯。
  - 之后换成绑好骨骼的 Tripo 模型，可以沿用同一套姿势。
  - 纯表现层：没有碰撞体，不挡准星，也不挡玩家；靠近玩家视点时自动隐藏。
- **流程**（`Phase`）：
  1. `WalkIn`：从东入口出发，绕过器械车，走到手术台西侧。西侧远离挂在东侧护栏上的手控器。
  2. `WaitClear`：束带没解开时，面向手术台等待，直到三条全部解开。
  3. `TurnAround` → `SitDown`：背对手术台，坐上台边，小腿垂下。
  4. `SwingIn`：腿收上台，变成长坐。
  5. `LieBack`：向后躺下，上半身跟随背板角度（椅姿 38°，平躺 0°），实时跟随手控器调整。
  6. `AwaitStraps` → `Secured`：玩家扣上三条束带。
  - 三条全部解开后倒序执行：`SitUp` → `SwingOut` → `StandUp` → `WalkOut` → `Idle`（离场）。
- **触发**：`SurgeryPatientRuntime.Current.Begin()`。编辑器和开发版可以按 `-` 键叫人进来（原 F7）。
- **提示**：屏幕顶部中央显示病人在等什么（"先解开三条束带" / "扣上三条束带 (n/3)"）。
- **配套改动**：`SurgeryTableV2Runtime` 新增只读的台面坐标系（`Floor`、`HeadDir`、`Right`、`PadTop`、`BackAngle`、`HeadAngle`）和束带计数（`StrapsClosed`、`StrapCount`）。
- **测试**：`SurgeryPatientFlowTests`（截图 `surgery-00..12`）。
  - 走入路径不碰任何实体碰撞体；
  - 束带未解开时不上台；
  - 躺下位置正确：髋部在座板上，脚跟不超出腿板，头部贴着背板（椅姿和平躺都检查）；
  - 三条束带扣上后进入 `Secured`，全部解开后起身离场；
  - 阶段顺序与上面完全一致。
- 只读探测工具：`Editor/SurgeryPatientProbe`（台面坐标系和周围碰撞体）。

## 21. 义体更换手术：近景手术（2026-10-22）

**近景模式**（`Runtime/SurgeryCloseupRuntime.cs`）
- 镜头：复制维修台的检视相机（同样的镜头参数、URP 设置和复古画面，按检视相机的清晰度渲染），对准他的右前臂，从房间视角平滑过渡进来。

  - 点部件 = 选中；

## 23. 信号接收器原型：看症状、用表量、对症修（2026-10-26，偏轻松）

参考《维修物语》（ReStory）的做法，并补上它被批评缺少的诊断环节。先在接收器上做原型，另外三件暂不改。

- **每单随机一个故障**（`RepairPropFlowDefinition.faults`，状态 `fault`）。三种都来自同一个原因：机器泡过海水。
  | 故障 | 初测症状（只报现象） | 怎么修 | 用件 |
  |---|---|---|---|
  | 射频接口小板损坏 | 只有噪声，信号强度 0，完全锁不上 | 换射频接口小板 | 1 块小板 |
  | 射频同轴线接头氧化 | 信号很弱（−68 dB），几秒丢一次锁 | 释放接头 → 清洁触点 | 不用 |
  | 电池连接线端子松动 | 锁上几秒后整机重启，轻敲也重启 | 断开供电 → 重新压紧端子 | 不用 |
- **初测只给症状**，接着列出三个嫌疑部位，并提示开盖后用万用表测量（偏轻松）。不再直接说“请检查射频小板”。
- **万用表**（新命令类型 `Measure`）：选中部件后点“测量 · …”。只能在关机、拔掉测试连接、开盖之后测，测量本身不改变任何状态。读数会直接说正常还是异常，异常时附带建议的修法（偏轻松）。
- **指引**：开盖 → 逐个测量（工单窗口里列出各嫌疑部位：未测 / 正常 / 异常）→ 找到原因后只带你走这个故障需要的步骤。没有坏的小板不会被拆。
- **修错了**：复测会显示“症状没有变化”。不罚钱，也不用件；指引回到开盖测量。如果误装了新小板，这块小板照样算用掉。
- **账目**：没用配件的修理照常交付（`ClinicCustomerTrade.noPartUsed`），存档校验也认可。
- **数据**：新增编辑器菜单 “Rebuild Flow Data Only”，只重建流程和工单数据，不动预制体。这次重建也把另外三件此前改过代码、但没重新生成的数据补齐了（故事发现、托盘归位条件）。
- 点击数（照指引走）：接收器换小板 22 次（加了 3 次测量），同轴接头 17 次，电池连接线更少。

## 24. 不同动作不同手感（2026-10-26，偏轻松）

参考《维修物语》：每类动作都有自己的手部动作，而不是点一下按钮就完成。四件道具都用同一套，因为它们的动作词汇一样。

- 点面板上的操作，或拿着对应工具点部件，不再立即执行。部件上方会出现视窗小部件，做完动作才真正执行。做的过程中流程状态不变。按 Esc 或点别的操作就放弃，没有代价。
  | 动作 | 用在哪里 | 怎么做 | 部件跟着动 | 声音 |
  |---|---|---|---|---|
  | 拧出 / 拧紧 | 所有螺钉 | 按住左键绕螺钉画圈：拧出逆时针，拧紧顺时针，一圈完成。反方向不算，并提示“方向反了” | 螺钉边转边退出 | 棘轮咔哒，越拧越高 |
  | 撬开 | 取下盖板 | 按住盖板顺着箭头拉，到底“啪”一声；中途松手会弹回 | 盖板越拉抖得越厉害 | 撬开声 |
  | 压回 | 盖板归位 | 逆着取出方向压到底 | — | 咔 |
  | 拔插头 | 断开内部供电、释放信号接头 | 先按住卡扣不动约 0.35 秒（圈填满变绿），再顺着箭头拔；没松卡扣就拔会提示“卡住了” | 插头被拔出一点 | 卡扣咔、拔出声 |
  | 插回 | 接回供电、插回接头 | 对准插座顺着箭头推到底 | — | 咔哒 |
  | 抽出 / 装入 | 模块、托盘 | 按住顺着箭头拖 | 模块跟着滑出一半 | 滑动声 |
  | 擦拭 | 清洁同轴接头（接收器） | 在白色盐渍上按住来回擦，盐渍逐渐变淡，十来下擦干净 | — | 沙沙声 |
  | 压接 | 压紧电池端子（接收器） | 按住加力，压力表指针进绿区（55%–88%）时松手；太早或压过头都只是重来 | — | 咔 |
  | 测量 | 万用表（接收器） | 把红表笔拖到圈出的测量点上松手；表上的数字先跳动再定住（如 18.0 Ω、OL，接触不良时在 0.1 Ω 和 OL 之间来回跳） | — | 正常哔一声，异常是警告音 |
  | 一下完成 | 开关机、测试座、测试、展开护条、交付 | 和以前一样 | — | — |
- **电动起子**：面板上“批量”按钮（卸下 / 装回全部螺钉）不用一颗颗画圈，螺钉依次自动转出或转入，每颗约 0.3 秒。成对的“断电并解除连接 / 接入并通电”仍然一下完成。
- 留存原件（如主板）不会被移动，因为流程会检查它的姿态。动作结束、执行前，部件都会放回原位，所以拆装动画照旧由台面负责。
- 手感数值在 `RepairPropGestureLogic`，不依赖场景，可单独测试。哪类命令用哪种动作在 `RepairPropFeel.For`；数据里可以用 `PropCommand.feel` 单独指定（接收器的擦拭和压接就是这样指定的）。万用表显示值是 `PropProbe.normalDisplay / abnormalDisplay`，已重建数据。
- 测试：
  - EditMode `RepairPropFeelTests`：四件道具的每条命令都对应正确的动作；每种动作的通过方式和失误方式（反方向、提前松手、没松卡扣、擦到盐渍外、压力不够或过头、表笔没碰到测量点）。
  - PlayMode `Receiver_ByHand_*`：真实场景里用模拟鼠标把接收器三种故障各完整修一遍，每个动作都必须做完并真正执行。
  - 原来按面板逐条点击的场景测试，在各测试程序集里统一关掉手感（`RepairPropTestPins`，并固定接收器故障）。
