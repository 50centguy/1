# 四件验收场景的模型开销与 VR 性能预算（2026-10-20 实测）

测量方法：`ScenePerformanceBudgetTests`（PlayMode）在 Play 状态下统计所有实际渲染的渲染器（`forceRenderingOff` 已排除）：三角面、渲染器、材质槽、唯一材质、贴图运行时内存、实时灯和投影。每个视角的数据是视锥裁剪估算：批处理模式下 UnityStats 不出数，所以没算遮挡剔除，也没算合批。结果在 `scene_cost_20261020.json`。设置环境变量 `BORDER_REPAIR_PERF_REPORT` 可以重新生成。

## 结论

1. **三角面的大头不在这次新做的三件。** 维修台、手术台、龙门三件加起来 5.7 万面（13%）；机器人 / 维修座占 24.8 万（57%）；原工作台残留的 17 张便签和标签每张 3,752 面，共 6.4 万，按资产清单原本每张只有 12 面。
2. **对 VR 来说，材质槽、投影和全屏特效比面数更要紧。**
   - 新三件按物体拆了多个材质，共 259 个材质槽，平均每个物体约 2.4 个；
   - 597 个渲染器全部投射阴影；
   - 四件道具的贴图有 73 MB（接收器基础色 4096）。

## VR 预算建议

当前 VR 原型走的是 Quest Link / PC VR，渲染在电脑显卡上完成；如果以后要做 Quest 一体机，预算要严得多。

| 指标（每帧、单眼视野） | PC VR 90 Hz 目标 | Quest 一体机 72 Hz 目标 | 现在（最坏视角） |
|---|---:|---:|---:|
| 可见三角面 | ≤ 400k | ≤ 150k | ≈ 418k |
| 合批后的绘制 | ≤ 600 | ≤ 150 | 估计 400–670 |
| 带阴影的实时灯 | ≤ 2 | 0（烘焙） | 3 |
| 全屏后处理 | 1 道，可降分辨率 | 不用 | 桌面版有 PS2 + 柔光两道（VR 下不开启） |
| 贴图内存 | ≤ 512 MB | ≤ 200 MB，用 ASTC | 132 MB |

## 控制手段（按收益排序）

1. **机器人 / 维修座做 LOD**：Blender 减面出 50% 和 20% 两级，加 LODGroup。房间远景用低级 LOD，预计能省 12–18 万面。这一步碰到 RobotV4，按约定要你确认后才动。
2. **原工作台残留的便签和标签换成两个三角形的贴图面片**，能省约 6.3 万面，几乎没有代价。
3. **新三件做贴图图集**：每件一张 1024 图集、一个材质，材质槽从 259 降到约 10，再加静态合批（台面、手术台主体、龙门环都不动）。会动的部件保持独立。
4. **关掉小物件的投影**：螺丝、标签、线缆、贴纸这类小于 5 cm 或在内部的东西不投影，预计投影物体能少一半以上。
5. **灯光**：
   - 房间里 12 盏补光改成烘焙，加光照探针；
   - 实时投影只保留维修台台灯和手术无影灯，而且只在玩家靠近时开投影。
6. **四件道具的贴图**：接收器上限 2048、其余 1024；御守 110 个材质合并。这一项需要你先定美术方案（之前的 TX-1、OM-1）。
7. **剔除**：
   - 烘焙遮挡剔除（房间是环形，隔墙多）；
   - 小杂物所在图层设 4 m 剔除距离（`Camera.layerCullDistances`）。
8. **VR 专属设置**：
   - 单通道实例化（Single Pass Instanced）；
   - 用 MSAA 4x，不用后处理抗锯齿；
   - Quest 打开注视点渲染（FFR）；
   - 渲染缩放先用 1.0；
   - PS2 / 柔光在 VR 下保持关闭。现在就是只在桌面场景开启的。
9. **把预算写进测试**：在 `ScenePerformanceBudgetTests` 里给每个模块和每个视角加上限断言（例如每件新道具 ≤ 25k 面、≤ 30 个材质槽），以后新加的模型超标就会直接报失败。

## 2026-10-20 更正与第 2、3 项结果

- **更正**：
  - 原来统计的“原工作台残留 6.4 万面”不对：那 17 张便签和标签被 Unity 静态合批进了同一个合并网格，统计时把整个合并网格重复算了 17 次。它们实际只有 504 面，所以第 2 项不需要做。
  - 改正统计方法后：全场景 35.1 万面，机器人 / 维修座占 24.8 万（71%）；各视角可见面数为入口 6.2 万、手术台旁 28 万、维修台前 2.6 万。
- **第 3 项已完成**（`ArtSource/RepairBenchV2/atlas_bake.py`）：
  - 维修台、手术台、龙门都在 Blender 里烘焙成一张图集（颜色图一张，金属度 / 光滑度另一张），用一个 URP Lit 材质。
  - 只有平色发光件（LED、灯泡、镜头），以及整件都是印刷图案的物体（维修垫网格、抽屉标签、便签、CRT 屏）保留原材质，这样印刷图案保持清晰。
  - 每件独立材质数降到 4–9 个。
  - 运行时把不会动的部件静态合批（`V2StaticBatch`）：维修台 28 个、手术台 19 个、龙门 16 个渲染器合并；会动的抽屉、工具、垫板、托盘、机械臂不合批。
  - 三件合计的绘制次数从约 259 降到约 70。全场景材质槽从 751 降到 616，唯一材质从 78 降到 64；维修台视角的材质槽从 129 降到 82。
  - 数据见 `scene_cost_20261020_atlas.json`。
  - 回归：RepairProps PlayMode 39/39，TwoNight PlayMode 36/36。
