## 2. 维修选择要改名

| 旧选项（`RobotRepairChoice`） | 旧界面文字 | 改为 | 对应的拆装路径 |
|---|---|---|---|
| `RebalanceRotor` | 重新做转子动平衡 | **翻修原引擎（换轴承）** | 当前局部路径：锁扣 → 上盖总成 → 左上轴承（加进气口清理）。不用拆机身、不用卸引擎 |
| `ReplaceMotorCore` | 更换马达芯 | **换整台左引擎** | 需要旧路径里的 10L（断开外露线缆、取下左引擎）。不需要 10La–10Lc |

- **选择的时机要改**：旧会话要拆完全部 13 步、“露出马达芯”后才让选。新的两个选项在**诊断完成后**（看过右侧对照、进气口、保养记录、磨损轴承）就该选，选完再走各自的拆装路径。
- **改名方式**：`RobotRepairSession.cs` / `RobotRepairPlan.cs` 是从主工作区**原样导入**的（主工作区里还没提交）。改枚举会和主工作区那份分叉。建议二选一：
  - 在七号的包装层做映射（`ChoiceLabel` 已经在包装层），不动导入文件；
  - 或者先和主工作区确认，再一起改。

## 4. 迁移清单（建议顺序）

1. **维修座第二阶段 + “允许结束维修”接口**：
   - 把工单线的维修座改动搬到表现线：状态 8–10、`LiftOff`、`IDockServiceCompletionGate`、`RotorPowerDriver.IsAtIdleSpeed`。
   - **同时**让 `FirstOrderFlow` 实现这个接口，把 `PendingRepairs` 作为 `CanFinishService` 的理由。
   - 删掉 `FirstOrderFlow.LiftOff` 里自己移动七号的代码，改用维修座的离座。
   - 不能只搬维修座：维修座要求有接口才允许恢复供电，`FirstOrderFlow` 的通电会被拒绝，它自己的离座协程也会和维修座的 `LiftingOff` 冲突。
2. **维修选择**：按第 2 节改名，放到诊断之后；“翻修原引擎”接当前局部路径。
3. **部件表拆成两份**：
   - 翻修 = 锁扣、上盖、轴承；
   - 换整台引擎 = 10L 起（先核实 1–9 是否必要）。
   - 检查点：旧会话要 3 个锚点（左上盖、左护栅、外露线缆插头）。切片的观察项是右引擎对照、左进气口、保养记录、原位轴承、新旧对比，合并成一份。
4. **通电前检查**：保留为单独一步。表现线的工作台没有零件盘 / 磁性盒的取放，这一条先标为不适用或占位。
5. **复测**：决定是否采用“悬停 + 负载、可失败重来”。采用的话，`FoStep.Retest` 要拆成两步，并加失败回到停靠。
6. **安全故障锁定和工号复位**：接口搬过来以后再接。切片里没有绕过的入口，现在不需要。
7. **工单记录**：给 `Acted` 加上 `UNIT07` / 工单 ID、阶段和维修座状态。
8. **界面**：工单线的 IMGUI 面板换成切片的 UGUI 面板。`IDockClickBlocker` 可以由 EventSystem 的界面射线代替。工单号输入框按切片的规则处理：有焦点时不触发快捷键。
9. **不合并**整条工单线。导入的 5 个通用工单文件（`Core/RepairSession.cs` 等）仍然不要带进来。
