## 1. 场景层级与写死的世界坐标

- **场景里的东西**：
  - 工作台预制体 `WorkbenchArea` 在原点，包含整个房间：地面、三面墙、杂物。z = 1.70 一侧敞开。
  - 维修架 `Unit07ServiceDock` 和七号 `UNIT07_RobotV4_DockReady` 是两个独立实例。
  - 首单部件、落点、镜头、灯光由构建脚本加在场景实例上。
  - 详见 `audit_layout_A.txt`。
- **工作台不动，只移动维修架。** 工作台连着整个房间，所以 B 只移动“维修架 + 七号”。
- **写死世界坐标的地方。** 全在场景构建脚本里，运行时流程和维修架控制器都不依赖世界坐标。我把它们改成按“布局”参数生成，A 的参数就是原来的值。

| 写死的值 | 影响 | 处理 |
|---|---|---|
| 维修架位置 (0, 0, 1.15)、朝向 180° | 整个布局 | 改成布局参数 |
| 维修座镜头位姿 | 布局换了会拍不到夹具和开关 | 随维修架一起变换 |
| 左引擎 / 背面 / 右引擎 / 近看镜头的偏移方向（世界轴） | 维修架一转，镜头会跑到七号背后 | 偏移方向随维修架旋转 |
| 总览镜头 | 只适合 A | B 单独给（玩家身后上方） |
| 维修座检修灯 | 照不到 B 的维修架 | 随维修架一起变换 |
| 工作台镜头、台灯、顶灯、上盖翻面后文字朝向（朝 +Z） | 都跟工作台走 | 不用改：工作台没动，玩家都站在工作台前 |

- **测试的适配。** 首单的 EditMode 和 PlayMode 测试改成参数化，在原场景、A、B 三个场景上都跑一遍。逐帧运动监视从测试程序集挪到运行时（`FirstOrderMotionMonitor`），供布局实测复用。
- **其他代码改动**：
  - 验收驱动加了“虚拟鼠标设备”点击方式；
  - 点选输入加了 `LastClickHit`，只读，记录最近一次点中的对象。
- **没有改的**：维修流程、点选规则、搬运逻辑都没改。

## 2. B 是怎么摆出来的

不是凭感觉摆的，用 `LayoutPlanner` 搜索（`planner_B.md`）。

**搜索范围**：

- 维修架锚点：先按 10 cm 网格粗搜，再在前 12 名周围按 2.5 cm 细搜。
- 朝向：粗搜每 15° 一档，细搜每 5° 一档。
- 玩家站位：5 cm 网格。

**硬条件**：

- 维修架和七号不碰工作台、房间物件、墙。
- 操作垫正前方 0.50 × 0.45 m 留给人站。
- 七号能从敞开一侧直线进出（1.05 m 宽的通道）。
- 够得着：
  - 左引擎 ≤ 0.80 m；
  - 开关、握把 ≤ 0.95 m；
  - 操作垫、托盘、轴承盒 ≤ 1.00 m。
  - 这张工作台前，不存在三者同时在 0.85 m 内的站位，所以要前倾半步。
- 维修架在玩家左前、工作台在右前。

**评分**：按首单动作顺序算站位处的转向（大于 90° 的次数优先，其次总转角）。排名靠前的候选，再用真实碰撞核对从玩家眼睛能不能点到关键部件。

**结果**：

- 维修架锚点 (0.375, 0.825)，在 A 的朝向上再转 105°。
- 七号左引擎和断电开关朝向玩家。
- 玩家站位 (−0.40, 0.45)，朝向 49°（面向工作台偏左）。

**备注**：

- 搜索中途发现第一版候选把维修架摆到了操作垫正前方，人站不过去，于是加了“操作垫前留空”这条硬条件重搜。
- B 里七号左引擎悬在原有的凳子 `Furniture_Stool` 上方：七号最低 0.72 m，凳面 0.64 m，没有碰。显得更挤，这一点需要美术判断。

## 4. 三个特别检查

- **上盖翻面阅读**：A、B 一样，因为工作台和操作垫没动。
  - 从站位眼睛（约 1 m 外）看过去，翻面上盖的内侧被台灯照得发白，**保养标记读不出来**（`*_M2_cover_on_mat_stand*_readRecord.png`）。
  - 按 7 用“保养记录”近景镜头可以读。
  - 对 VR 来说是问题，需要调灯光或让玩家凑近，两种布局都要处理。
- **旧 / 新轴承对比**：两种布局里，两个轴承都在同一画面里（`*_M3_compare_*`）。
  - B 站位离托盘和轴承盒只有 0.7–0.8 m，看得更清楚。
  - A 的站位夹在工作台和维修架之间，看工作台要先转过身。
- **离座复测**：两种布局七号上方都是空的，复测都通过（占位判定）。
  - B 站位看七号是左前方 +67°，能看到正脸和左引擎。
  - A 要转回身后看（`*_M4_retest_stand*_watchRetest.png`）。

## 5. VR 几何评估（`geometry_vr.md`，**未用头显验证**）

**模型**：人体半径 0.25 m、高 1.85 m；站直肩高 1.40 m，伸手 0.70 m；弯腰或下蹲时肩高 1.00–1.45 m，伸手 0.85 m；手从目标上方 12 cm 落下。

- **B**：
  - 原地能完成：左上盖、进气口、外侧锁扣、左上轴承、断电开关、托盘、轴承盒。
  - 操作垫要走 1 步，而且附近能站的位置只有约 0.04 m²，比较挤。A 有 0.12 m²。
  - 主站位能放下的最大人体半径 0.31 m；A 是 0.45 m。
- **A**：
  - 原地能完成：引擎类动作和断电开关。
  - 操作垫、托盘、轴承盒都要转身再走 1 步。
- **两者共同**：
  - 后侧锁扣附近找不到既能站、手又能直接伸到的位置：手会先碰到上盖边沿，约 6 cm。
  - 夹具握把在七号背后，要绕 2–3 步。

## 6. 推荐与要你确认的事

**推荐 B。** 主要维修动作（拆上盖、清进气口、取旧轴承、放旧件、拿新件、装回）都在玩家前方 ±70° 内完成。大于 90° 的转向从 6 次降到 2 次，总转角少一半多，搬运同样不穿模。房间物件都没删，七号悬在凳子上方，气质只会更挤。

要你确认：

1. **剩下的两次大转向**都发生在引擎和右端的托盘 / 轴承盒之间（100° / 110°）。
   - 原因：托盘和轴承盒在工作台最右端。
   - 不改流程，就只能接受这两次转向。
   - 将来如果允许，可以把旧件 / 新件位置挪到维修架自带的零件盘 `Dock_PartsTray` 或工作台左端。这次按要求没做。
2. **B 的操作垫前比较挤**（VR 下要侧身半步），七号左引擎悬在凳子上方。需要美术和你看截图判断。
3. **保养标记在台灯下读不清**，两种布局都要处理。

## 7. 请你真人试玩的方法

在 `BorderRepairStation_layoutab` 工作树里打开 `Scenes/LayoutAB/Unit07FirstOrder_LayoutA.unity` 或 `…_LayoutB.unity`，按 Play，用鼠标点。按 1–9 切镜头：

| 键 | 镜头 |
|---|---|
| 1 | 维修座 |
| 2 | 左引擎 |
| 3 | 背面 |
| 4 | 工作台 |
| 5 | 总览 |
| 6 | 右引擎 |
| 7 | 保养记录 |

原型是固定镜头，所以“转身”的差别主要体现在镜头切换的方向和总览画面上。第一人称或 VR 的转身感受，要等有自由视角之后才能真正试。
