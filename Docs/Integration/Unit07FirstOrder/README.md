## 2. 场景与交互（`Assets/BorderRepair/FirstOrder/Scenes/Unit07FirstOrder_Test.unity`）

### 布置

- 工作台在原点；维修座在工作台前方 1.15 m，转 180° 正面朝工作台；七号对齐 `Dock_RobotAnchor`。
- 玩家站在两者之间：转身面对七号拆零件，转回工作台放零件。
- 工作台自带的义肢占位件 `WB_Placeholder` 在本场景里关掉，腾出操作垫当落点。

### 点选

只在场景实例上加，不改预制体。

- 锁扣、上盖总成、轴承、右引擎上盖各有一个触发盒点选代理。
- 七号和维修座的 268 个网格加了遮挡用 MeshCollider：被机身挡住的部件点不到。例如从正面点不到后侧锁扣，必须换到背面镜头。
- 维修座集成留下的整块左引擎检查代理，在“开始检查左引擎”之后关掉，否则它会盖住锁扣、上盖和轴承。

### 镜头

按 1–6 手动切换；每一步也会自动切到合适的镜头。

| 键 | 镜头 | 用途 |
|---|---|---|
| 1 | 维修座 | 侧前方，七号落座后仍看得到夹具握把和断电开关 |
| 2 | 左引擎 | 外侧锁扣、上盖、轴承 |
| 3 | 左引擎背面 | 后侧锁扣 |
| 4 | 工作台 | 落点、轴承盒 |
| 5 | 总览 | 同时看到引擎和工作台，用于放下零件 |
| 6 | 右引擎（对照） | 对照正常的右引擎 |

### HUD

- 当前步骤、下一步提示、最近一次反馈（包括拒绝原因）。
- 指向的对象、维修座状态和转速。
- “零件去向”：每个零件此刻在哪。

### 拆下路径的几何检查

方法：移动件用它自己的精确网格碰撞，周围零件临时用凸包，再用 `Physics.ComputePenetration` 判断是否穿入。

- **上盖总成**抬起 10 cm：检查了 7 个邻近零件，都能判定，没有穿入。
- **旧轴承**抬起 7 cm：没有穿入。转轴与轴承同轴套装，不计入。
- 下壳 `Engine_LowerCover_L` 是包在轴承外面的壳体，凸包会把它填实，所以这一项**判断不了**，不算通过。
- 部件文档里的疑问——“轴承能否直接取出，还是要先拆电机支架”——从几何看，上盖总成拆下后轴承可以沿轴直接抬出，电机支架在轴承下方，不挡路。这只是几何推断，**仍需美术确认**。

## 6. 本轮查出并修正的问题

1. **工作台材质的高光开关用反了（在 `art/workbench-area` 修正，`2c8a38c`，已合入）。**
   - 原因：URP 17 Simple Lit 的 `_SpecularHighlights` 是枚举，0 = 有高光，1 = 无高光。之前设成 0，材质一重新导入，`_SPECULAR_COLOR` 就会被 URP 打开。
   - 发现经过：在新工作树里，工作台原有的导入测试失败了。
   - 画面没有变化，因为高光色本来就是黑色。
   - 修正后，工作台工作树里的 EditMode 12/12；合入后，工作台的 EditMode 和 PlayMode 测试都在本分支的全量回归里通过。
2. **预制体根节点旋转。** 维修座、工作台预制体的根节点带 FBX 轴向换算旋转，不能直接覆盖成 0° 或 180°，要在外面再叠一层。已修正，并由“七号直立、工作台台面 0.90 m”测试锁住。
3. **镜头与遮挡。** 见第 4 节，由验收驱动查出：夹具握把在落座后被手臂挡住；右引擎在维修座镜头外。
4. **维修座原有测试的查找歧义（在本分支修正）。**
   - 问题：`Unit07DockPlayModeTests.PowerOffDoesNotBreakGripperAnimation` 用不排序的按名查找取 `Arm_R_JawUpper`，但模型里有两个同名对象：骨骼，和骨骼下的同名网格。拿到网格时，它的本地旋转不变，测试读到 0°。
   - 表现：原分支上连跑 3 次都通过；在本集成项目里对象枚举顺序不同，3 次失败 2 次。
   - 修正：改为比较世界旋转，两个对象在落座时都会随夹爪动画转动。修正后连跑 5 次全部通过。
   - 夹爪动画本身没有问题。这个修正也应带回 `integ/unit07-dock-phase1`。
